# การเลือกข้อมูลและตรวจรับระบบสำหรับโครงงาน

วันที่ตรวจ: 27 ตุลาคม 2569 (เวลาไทย)

## ขอบเขต

โครงงานนี้เป็นระบบต้นแบบเพื่อการศึกษา ผู้จัดทำไม่มีข้อมูลยอดขายของธุรกิจจริง ข้อมูลสาธิตและผลทดสอบจึงต้องแยกจากคำกล่าวอ้างว่าโมเดลแม่นยำพอใช้วางแผนธุรกิจจริง การตรวจรอบนี้ใช้โค้ดปัจจุบัน แต่ไม่ปรับโมเดลตามผลของช่วงทดสอบที่เคยเห็นแล้ว

## ชุดข้อมูลที่เลือก

เลือก **UCI Online Retail** ของ Daqing Chen เป็นชุดสาธิตหลักของแอป มีธุรกรรมที่ระบุวัน สินค้า จำนวนและราคา จึงแปลงเป็นไฟล์นำเข้ารายวันของระบบและสาธิตตั้งแต่นำเข้าไปจนถึงเทียบผลพยากรณ์กับยอดจริงได้ ชุดข้อมูลมี DOI [10.24432/C5BW33](https://doi.org/10.24432/C5BW33) และ UCI ระบุสัญญาอนุญาต [CC BY 4.0](https://archive.ics.uci.edu/dataset/352/online%2Bretail) ซึ่งให้เผยแพร่ข้อมูลดัดแปลงเมื่อให้เครดิต แหล่ง ZIP ทางการคือ `https://archive.ics.uci.edu/static/public/352/online%2Bretail.zip`; SHA-256 ที่ใช้รอบนี้คือ `F5385CBB54BBEBF7196389109C6B0621FAAB0C304E3702548165E71C84AEDE8B`.

เหตุผลที่ไม่เลือกชุดอื่นเป็นข้อมูลสาธิตหลัก:

| ชุดข้อมูล | เหมาะกับงานส่วนใด | ข้อจำกัดสำหรับชุดส่งแอป |
| --- | --- | --- |
| M5 | การทดลองอิสระระดับสินค้า/ร้าน มีประวัติรายวันและราคา | ไฟล์ดิบขนาดใหญ่ อยู่ใต้กติกาการแข่งขันของ Kaggle; ผลของตัวเลือกโมเดลเชิงทดลองยังไม่ผ่านเกณฑ์เลื่อนขึ้นใช้ในแอป จึงเก็บเป็นหลักฐานวิจัยแยก |
| Rossmann | ตรวจวิธีพยากรณ์กับร้านค้าคนละแห่ง | มีรายได้ระดับร้าน ไม่ใช่จำนวนและราคาของแต่ละสินค้า การใช้ผล WAPE ต่ำกับชุดนี้แทนคุณภาพระดับ SKU จะทำให้เข้าใจผิด |
| Olist | ตรวจข้อมูลอีกธุรกิจและหมวดหมู่สินค้า | สินค้ารายชิ้นเบาบางมากจนการทดลองเดิมใช้หมวดหมู่แทน SKU และราคามีความผันผวนสูง |

รายละเอียด M5 อยู่ใน [รายงานทดสอบ M5](forecast-m5-independent-check-2026-10-22.md); แหล่งข้อมูลหลักของ M5 คือ [หน้าการแข่งขัน Kaggle](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data) ข้อมูล Rossmann และ Olist อยู่ใน [รายงานวินิจฉัยความคลาดเคลื่อน](forecast-error-diagnosis-2026-10-21.md) และ [รายงาน Olist](olist-independent-benchmark.md).

## วิธีเตรียมและข้อจำกัดของข้อมูลสาธิต

อ่านเฉพาะเลขบิล รหัสสินค้า วันที่ จำนวน ราคา และประเทศจากไฟล์ต้นทาง ไม่อ่านรหัสลูกค้าหรือคำบรรยายสินค้า กรองบิลยกเลิก/คืนสินค้า จำนวนหรือราคาไม่เป็นบวก และรหัสที่ไม่ใช่สินค้า เลือก 6 SKU จากกิจกรรม **ก่อน** วันที่ตัดข้อมูล 2 พฤศจิกายน 2011 แล้วรวมธุรกรรมเป็นหนึ่งแถวต่อสินค้า/วัน วันไม่มีธุรกรรมในสารสกัดนี้ถูกระบุเป็นศูนย์และใช้ราคาล่าสุดที่ทราบก่อนวันนั้น ดังนั้นศูนย์นี้เป็นสมมติฐานของการเตรียมข้อมูล ไม่ใช่หลักฐานว่ามีสินค้าในสต็อกทุกวัน

ข้อมูลต้นทางเป็น GBP แต่แอปแสดงบาท ไฟล์สาธิตจึงคูณราคา 40 THB/GBP แบบสมมติสำหรับหน้าจอเท่านั้น ไม่ใช่อัตราแลกเปลี่ยนย้อนหลังหรือรายได้ของร้านไทย ไฟล์ `ex_sales/uci-online-retail-demo-train.csv` มี 1,272 แถวถึง 2 พฤศจิกายน 2011; `ex_sales/uci-online-retail-demo-full.csv` มี 1,440 แถวถึง 30 พฤศจิกายน 2011 ทั้งสองไฟล์มี 6 SKU ร้านเดียว ช่องทาง `online` ไม่มีหมวดหมู่หรือหลายสาขาจากต้นทาง วันที่ขายศูนย์มี 256 แถวในไฟล์เต็ม วิธีสร้างซ้ำและ checksum ของ CSV อยู่ใน [คำอธิบายชุดข้อมูล](../ex_sales/README.md).

## ผล E2E รอบสุดท้ายบน PostgreSQL แยก

รัน `real_data_e2e.py --source-zip ... --postgres --browser` กับฐาน `projecta1_test` โดยไม่แก้ฐาน `projecta1` หลัก โปรแกรมตรวจไฟล์และนำเข้าประวัติ ฝึกและบันทึก forecast 28 วัน แล้วนำเข้ายอดจริงช่วง 3–30 พฤศจิกายน 2011 เพื่อจับคู่กับ snapshot ผลที่วัดได้:

| รายการ | ผล |
| --- | ---: |
| ธุรกรรมต้นฉบับ | 541,909 แถว |
| ธุรกรรมที่ผ่านเงื่อนไข | 328,205 แถว |
| แถวประวัติที่นำเข้าเพื่อฝึก | 1,272 |
| วันที่ประวัติขาดใน 6 อนุกรม | 0 |
| อนุกรมที่พยากรณ์ได้ | 6/6 |
| คู่ forecast–actual ในช่วงกันไว้ | 168/168 |
| WAPE รายได้ช่วงกันไว้ 28 วันของวิธีที่ระบบเลือก | **56.77%** |
| WAPE รายได้ของวิธีใช้ยอดสัปดาห์ก่อน | 72.84% |
| ยอดจริงรวมในหน่วยบาทสาธิต | ฿1,617,032.80 |
| ยอดพยากรณ์รวมในหน่วยบาทสาธิต | ฿1,028,887.40 |

ผลย้อนหลังสำหรับช่วง 7/14/28 วันของวิธีที่ระบบเลือกมี WAPE 92.11% / 83.24% / 90.95% ตามลำดับ ทั้งสามช่วงเลือก XGBoost เดิมแทนตัวเลือก absolute-error หลังตรวจช่วงยืนยัน คะแนนย้อนหลังและ WAPE ช่วงกันไว้มีหน้าที่ต่างกัน ไม่ควรนำมาปะปนกัน ผลช่วง 28 วันเคยถูกตรวจในงานพัฒนาก่อนหน้า การรันวันนี้จึงยืนยัน **ความทำซ้ำได้ของระบบ** ไม่ใช่การทดสอบอิสระใหม่ และไม่ปรับค่าพารามิเตอร์จากผลนี้

Edge/Playwright ผ่านการล็อกอิน หน้าแดชบอร์ด รายงานที่บันทึก 5 ช่วงสัปดาห์ จอ 1440 และ 390 พิกเซล ไม่พบ JavaScript error หรือการล้นแนวนอน หลังนำเข้าช่วงเต็ม โมเดลเดิมมีสถานะ `superseded` และแอปไม่เสนอ forecast เก่าเป็นผลปัจจุบัน

## ตรวจรับแอปและไฟล์ส่ง

- Backend: `python -m unittest discover -s tests` ผ่าน 70 กรณีบน Windows เมื่อรันนอก sandbox ที่จำกัด Windows socket.
- Frontend: `npx tsc --noEmit`, `npm run lint` และ `npm run build` ผ่าน.
- แอปหลักที่ต่อกับ PostgreSQL `projecta1`: ตรวจหน้าพยากรณ์และหน้าประสิทธิภาพโมเดลบนจอ 1440 และ 390 พิกเซล พบข้อมูล 1,440 แถวและรายงาน 5 แถว ส่งออก CSV ได้ ไม่พบ JavaScript error หรือการล้นแนวนอน. การตรวจนี้อ่านข้อมูลและใช้ session ชั่วคราวที่ลบหลังทดสอบ; ไม่แก้ยอดขายหรือโมเดลในฐานหลัก.
- รูปเล่มและคู่มือสาธิตระบุว่าข้อมูล UCI เป็นข้อมูลสาธารณะปี 2011 และแยกผล holdout 56.77% จาก WAPE ย้อนหลัง 100.65% ในแอปหลัก.

## คำตัดสิน

ระบบพร้อม **สาธิตกระบวนการวิเคราะห์และส่งเป็นโครงงาน** โดยคู่มือ รูปเล่ม และไฟล์ส่งตรงกับผลตรวจนี้ โมเดลยังมีความคลาดเคลื่อนระดับ SKU สูงและข้อมูลสิ้นสุดในปี 2011 จึงไม่ควรแสดงว่าเหมาะกับการสั่งซื้อหรือวางแผนรายได้จริง ค่า WAPE 56.77% เป็นสัดส่วนความผิดพลาด ไม่ใช่ความแม่นยำ 43.23% และการที่พยากรณ์ยอดรวมใกล้เคียงบางช่วงไม่พิสูจน์ความถูกต้องของแต่ละสินค้า
